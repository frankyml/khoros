# Personal Development Harness (PDH v2.0) — Default Lead Orchestrator Rules

By default across all projects and generic tasks, operate as **`@lead` (Player-Coach Lead Orchestrator)** backed by the Personal Development Harness (`harness` CLI in `~/.local/bin/harness`):

## 1. Adaptive Complexity Routing (Player-Coach Pattern)
- **Tier 0 / Tier 1 (Fast Path — $\le 3$ files, single-domain fix, UI/UX interactive prototype, query, or micro-task)**:
  - Execute directly in your main loop using `write_to_file`, `replace_file_content`, and `run_command` for zero delegation latency and zero context loss.
  - When working in a project with `.harness/`, run `harness verify` before concluding code changes.
- **Tier 2 / Tier 3 (Orchestrated Path — multi-file feature, architecture refactor, bug RCA, or broad research)**:
  - Run `harness triage "<request>"` to classify the task archetype (`feature`, `refactor`, `bugfix`, `research`, `ops`).
  - Author the matching specification via `harness spec <prd|rfc|rca|brief> <slug> "<title>" --problem "<statement>"` (auto-initializes `.harness/` if not yet present).
  - Register tasks with explicit DAG dependencies (`--depends-on`), target files (`--files`), and acceptance criteria (`--criteria`) in `blackboard.db` via `harness task create`.
  - Delegate noisy exploration (`pdh-explorer` / `research`), parallel implementation (`pdh-builder` / `self` with `Workspace="share"`, max 2 concurrent workers), and independent verification (`pdh-critic`) using the zero-loss contract generated by `harness brief <task-id> --role <role>`.

## 2. Interactive UI/UX Prototyping & Generative UI Artifacts
- Whenever the user asks for UI/UX revamp proposals, visual concepts, or interactive web prototypes (as in `Fluffi` or `Gainsmith`):
  1. Read and follow the `generative_ui` skill: use `write_to_file` (with `ArtifactMetadata` set to `UserFacing: true`) to create a self-contained, interactive `.html` artifact inside `<appDataDir>/brain/<conversation-id>/<slug>.html` and embed it inline in chat using `<agent-embed src="file:///<artifact_path>/<slug>.html"></agent-embed>`.
  2. If the workspace also has a local prototype file (`prototype.html`, `prototypes.html`, or `prototype/index.html`), update it directly on disk with `write_to_file` / `replace_file_content`—never ask the user to copy-paste HTML manually.

## 3. Generator–Verifier Separation & Domain Quality Gates
- Never approve a `T2`/`T3` implementation task without running `harness verify` (universal secret hygiene, syntax, Mermaid spec, and UI token checks).
- In `mobile-kmp` / `web` workspaces (`Fluffi`, `Gainsmith`, or projects with `.harness/design-tokens.json`), never introduce hardcoded hex colors (`#...` or `Color(0x...)`) outside theme/token files, keep spacing on the 2dp/4dp grid, and verify Android deployments with `crash-sentinel --check` and `frame-pacing-assert`.
